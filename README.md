# Length generalization of small transformers on formal languages

## Question

How well do small trained transformers recognise simple formal languages on
inputs that are longer than the inputs they saw in training? How does the
positional encoding change this?

The models are trained on strings of length 1 to 40 and tested on strings of
length up to 200.

## Why it matters

Theoretical work describes which languages a transformer *can* express. A
trained model does not have to find such a solution. It can also find a
shortcut that works on the training lengths and fails on longer inputs.
Testing on longer inputs is a simple way to see which of the two happened.

## Languages

| Language | Strings in the language | Type | What it tests |
|---|---|---|---|
| Parity | binary strings with an even number of 1s | regular | counting modulo 2 |
| Equal-count | strings over {a, b} with as many a as b | not regular | exact counting, order does not matter |
| a^n b^n | a...a b...b with the same number of a and b | context-free | counting and order |
| Dyck-1 | balanced brackets, for example `(()())` | context-free | the depth never goes below zero |

Parity and equal-count depend only on how often each symbol occurs. a^n b^n
and Dyck-1 also depend on the order: `aabb` and `abab` have the same symbol
counts, but only `aabb` is in a^n b^n.

## Method

### Data

All strings and labels are generated by code (`flg/languages.py`). Each
language has a membership test, and the tests in `tests/` check it against
a second, independent implementation on every string up to length 12.

Negative examples are made from positive ones by a small edit, so that they
are hard to tell apart from positives:

- **count** negatives change the symbol counts (one symbol flipped, for
  example `aaabbb` to `aaaabb`).
- **order** negatives keep the counts and break the order (for a^n b^n and
  Dyck-1 only; for example `aaabbb` to `aababb`).

Every dataset is balanced: half positives, and the negatives are split
evenly between the kinds. For equal-count, a^n b^n and Dyck-1, every string
of odd length is negative, so only even lengths are used. Otherwise a model
could use the length alone.

| Split | Lengths | Size |
|---|---|---|
| train | 1 to 40, without 12, 24 and 36 | 20,000 |
| validation | same as train | 2,000 |
| test "train" | same as train | 1,000 |
| test "held out" | 12, 24 and 36 only | 1,000 |
| test bins | 41-80, 81-120, 121-160, 161-200 | 1,000 each |

The held-out lengths 12, 24 and 36 are never seen in training. They show
whether a model learned a rule or memorised the training strings. This
matters most for a^n b^n: there is only one positive string per length, so
the training set contains only 17 different positive strings.

The test sets are the same for every model and seed. The seed changes the
training and validation data, the weight initialisation and the batch order.

### Models

| Name | Model | Positional encoding | Attention |
|---|---|---|---|
| `nope_causal` | transformer | none | causal |
| `sinusoidal_causal` | transformer | sinusoidal | causal |
| `learned_causal` | transformer | learned | causal |
| `nope_bidirectional` | transformer | none | full |
| `lstm` | LSTM | (not needed) | (not needed) |
| `majority` | always predicts the most common training label | | |

All transformers have 2 layers, width 64, 4 attention heads and a
feed-forward width of 128. Causal models read the answer at the last token.
The bidirectional model reads it at a `[CLS]` token put in front of the
string. The LSTM has one layer with 64 hidden units.

With causal attention, a token can only see earlier tokens. This gives the
model some information about positions even without a positional encoding.
With full attention and no positional encoding, the model sees the string
only as a multiset of symbols: `aabb` and `abab` always get the same output.
For a^n b^n and Dyck-1 this gives a hard limit. The test bins are 50%
positives, 25% count negatives and 25% order negatives, and the model must
give the same answer to an order negative and to a positive with the same
counts. So its accuracy can be at most 75%. A test in `tests/test_models.py`
checks that the model really gives the same output for reordered strings.

The learned positional encoding has a table of 256 positions, but positions
after 40 are never used in training, so their vectors stay at their random
start values.

### Training

All models use the same settings: Adam with learning rate 0.001, batch size
64, at most 30 epochs. After each epoch the model is evaluated on the
validation set, and the best epoch is kept. Training stops when validation
accuracy is 1.0 or has not improved for 5 epochs. There is no
hyperparameter search. The long test bins are never used to choose a
model or a setting.

The configs for equal-count and a^n b^n train every model with 5 seeds.
The configs for parity and Dyck-1 train `nope_causal`, `sinusoidal_causal`
and `lstm` with 3 seeds. Results report the mean over seeds and the range
from the worst to the best seed.

## Related work

Sälzer, Köcher, Kozachinskiy, Zetzsche and Lin (ICLR 2026) study *counting
properties*. In their definition, a counting property is a language that is
closed under reordering: if a string is in the language, every reordering of
it is too (Definition 2.1). Parity and "more a than b" are examples. The
paper proves that softmax transformers with no positional encoding and no
masking can express every *semialgebraic* counting property, that is, every
property built from polynomial inequalities over the symbol counts
(Theorem 1.1). For transformers with average hard attention and no
positional encoding (NoPE-AHAT), these are exactly the counting properties
they can express (Theorem 1.2). As a consequence, parity cannot be expressed
by NoPE-AHAT (Corollary 4.2). The paper also trains such encoders on strings
up to length 500 and tests them on lengths 501 to 1000, with accuracy of at
least 0.94 (Section 6).

Our bidirectional NoPE model is close to the paper's setting, but it is not
the same model: it uses softmax attention, not average hard attention, so
Corollary 4.2 does not say that our model cannot learn parity. Equal-count
and parity are counting properties. a^n b^n and Dyck-1 are not. a^n b^n can
be written as the counting property #a = #b intersected with the order
language a\*b\*, in the way the paper describes for a^n b^n c^n (Section 2).
This project does not test the paper's theorems. It asks whether training
finds solutions that still work on longer strings, and how positional
encoding and causal masking change this.

> Sälzer, M., Köcher, C., Kozachinskiy, A., Zetzsche, G., Lin, A. W.
> *The Counting Power of Transformers.* ICLR 2026. arXiv:2505.11199.

## Setup

Python 3.12 and a CPU are enough.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
```

`requirements.txt` installs the CPU-only build of PyTorch.

## How to reproduce

One command per language trains all models with all seeds and writes the
results to `results/<language>/`:

```bash
.venv/bin/python run.py --config configs/parity.yaml
.venv/bin/python run.py --config configs/equal_count.yaml
.venv/bin/python run.py --config configs/anbn.yaml
.venv/bin/python run.py --config configs/dyck1.yaml
```

Then draw the plots:

```bash
.venv/bin/python plot.py results/dyck1
```

Output files:

- `metrics.csv`: accuracy per model, seed, test bin and example kind
  (`all`, `pos`, `count`, `order`)
- `runs.csv`: validation accuracy, best epoch, number of epochs and training
  time per model and seed
- `config_used.yaml`: the config and the Python and PyTorch versions
- `accuracy_vs_length.png`, and for a^n b^n and Dyck-1 also
  `accuracy_by_kind.png`

Observations:

- **Parity.** The LSTM is correct on every length up to 200. Both
  transformers stay close to 0.5 already on the training lengths, so they
  did not learn the rule with these settings. For them, the long bins say
  nothing about length generalization.
- **Dyck-1.** All three models do well on the training lengths, and all
  become worse on longer strings. The errors are of different kinds (mean
  over seeds, from bin 41-80 to bin 161-200):
  - The LSTM rejects almost every long valid string: its accuracy on
    positives falls from 0.95 to 0.01.
  - `nope_causal` accepts most long strings with wrong counts: its accuracy
    on count negatives falls from 0.53 to 0.18.
- The transformer results vary a lot between seeds, and there are only 3
  seeds. These are observations for this setup, not general claims.

## Limitations

- The models are small and all use one fixed set of hyperparameters. A model
  that fails here might succeed with other settings.
- The results are observations for these models, these lengths and these
  data distributions. They do not prove what transformers can or cannot do.
- a^n b^n has very few different training strings (17 positives).
- Short strings repeat often. For example, parity has only two strings of
  length 1. So the test "train" bin overlaps with the training data. The
  held-out bin does not.
- The Dyck-1 sampler does not give every balanced string the same
  probability. It shuffles the brackets and then rotates the string so that
  the depth never goes below zero.
- The majority baseline is 50% in every bin because the data is balanced.
  It is a check of the setup, not a strong baseline.
